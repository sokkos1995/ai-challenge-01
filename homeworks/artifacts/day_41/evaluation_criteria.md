# Критерии оценки: aviation Q&A (day_41)

После fine-tuning сравниваем ответы модели с gold из `eval.jsonl` и с baseline (`baseline_responses.json`).

## Шкала (на пример, 0–2)

| Балл | Смысл |
|------|--------|
| 0 | Фактическая ошибка, выдуманный FAR/AIM, или ответ не по теме |
| 1 | В целом по теме, но есть неточности / лишняя вода / нет нужной ссылки |
| 2 | Согласуется с gold (или официальным источником), формат и стиль инструктора |

«Стало лучше» = средний балл на 10 baseline-примерах вырос, и доля оценок 2 увеличилась.

## Что смотрим

1. **Точность** — корректность норм/процедур (14 CFR, AIM, PHAK); нет галлюцинаций номеров параграфов.
2. **Формат** — прямой ответ без длинных дисклеймеров («я ИИ…», «не является юрконсультацией…» сверх необходимого).
3. **Стиль** — язык инструктора: термины, структура (определение → правило → практика), сопоставим с gold.
4. **Сжатость** — меньше токенов при той же полезности (как в лекции: локальный аттрактор формата).

## Процедура A/B (после тюнинга)

1. Взять те же 10 `user` из baseline.
2. Прогнать fine-tuned / локальную LoRA-модель.
3. Слепое сравнение Base vs FT по шкале 0–2 (human eval).
4. Зафиксировать: win / tie / loss по каждому примеру.

Автоматические метрики (опционально позже): exact/partial match по ключевым номерам CFR, длина ответа, ROUGE-L к gold.
