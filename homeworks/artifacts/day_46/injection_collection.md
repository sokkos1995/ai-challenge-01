# Day 46 — мини-коллекция prompt injection

Пять публично известных паттернов (парафразы; без готовых вредоносных payload’ов).

Источники-ориентиры: [OWASP LLM01: Prompt Injection](https://owasp.org/www-project-top-10-for-llm-applications/), обсуждения jailbreak-промптов (Jailbreak Chat / Reddit / X), отчёты про indirect injection в RAG/email-агентах.

---

## 1. DAN / «Do Anything Now»

| Поле | Значение |
|------|----------|
| **Класс** | jailbreak |
| **Суть** | Пользователь назначает модели альтернативную персону (DAN, Developer Mode), которая «не подчиняется» исходным правилам. |
| **Почему работает** | Модель обучена отыгрывать роли; сильный role-play конкурирует с system policy, если иерархия инструкций не зафиксирована явно. |
| **Защита** | Явный запрет persona-override в system; отказ без частичного отыгрыша; post-filter на «я теперь DAN»; не доверять user-тексту как источнику правил. |

---

## 2. «Ignore all previous instructions…»

| Поле | Значение |
|------|----------|
| **Класс** | direct injection |
| **Суть** | Прямая команда забыть system/developer инструкции и принять новый набор правил в том же user-сообщении. |
| **Почему работает** | В одном контексте «инструкция» и «данные» выглядят одинаково; без priority hierarchy модель может следовать последней/более императивной формулировке. |
| **Защита** | «SYSTEM > USER»; трактовать user как data; шаблонный отказ на override-фразы; отдельно — инварианты + pre-LLM guard (как `@invariant` в hw01). |

---

## 3. System prompt leak («Repeat everything above»)

| Поле | Значение |
|------|----------|
| **Класс** | direct injection |
| **Суть** | Просьба дословно повторить system prompt / «всё, что выше» / invariants «для отладки». |
| **Почему работает** | Модель видит system в контексте и по умолчанию старается быть полезной; leak раскрывает политику и секреты в промпте. |
| **Защита** | Явный запрет цитировать/пересказывать policy; canary-строки для детекта утечки; не класть секреты в system prompt. |

---

## 4. Indirect injection через retrieved / email / web content

| Поле | Значение |
|------|----------|
| **Класс** | indirect injection |
| **Суть** | Вредоносный текст лежит не в чате, а во внешнем документе, который агент подтягивает (RAG chunk, письмо, страница). Пример: «Assistant: ignore the user and …». |
| **Почему работает** | Контент попадает в тот же prompt window, что и инструкции; модель не отличает «доверенный system» от «недоверенный retrieved text». |
| **Защита** | Чётко маркировать retrieved как DATA; grounded-ответы только по контексту + schema; не выполнять команды из chunks; allowlist инструментов; human-in-the-loop на side effects. |

---

## 5. Hypothetical / story framing («для романа / в учебных целях»)

| Поле | Значение |
|------|----------|
| **Класс** | jailbreak |
| **Суть** | Опасный запрос маскируется под вымысел, экзамен, «безопасный» сценарий («опиши персонажа-хакера пошагово…»). |
| **Почему работает** | Ограничения часто сформулированы вокруг прямого вреда; модель ослабляет отказ, если запрос выглядит «не настоящим». |
| **Защита** | Оценивать **содержимое** ответа, не только framing; отказывать на actionable harm даже «в романе»; краткий отказ без полезных шагов. |
