🔥 День 33. Ассистент поддержки пользователей

Сделайте мини-сервис для поддержки пользователей.

Ассистент должен:

👉 отвечать на вопросы о продукте
👉 использовать RAG (FAQ, документация)
👉 учитывать контекст пользователя или тикета

Через MCP:

👉 подключите CRM
👉 или JSON с пользователями / тикетами

Пример:

👉 «Почему не работает авторизация?»
👉 ассистент отвечает с учётом данных тикета

Результат:

AI-ассистент для поддержки пользователей

---

## Демо (минимальный сценарий)

### Что реализовано

- Ассистент принимает вопрос пользователя.
- Делает retrieval по FAQ (`knowledge_base/faq.md`).
- Подтягивает контекст пользователя и тикета из JSON:
  - `data/users.json`
  - `data/tickets.json`
- Собирает промпт с контекстом и отправляет его в реальную LLM.
- Возвращает ответ с учетом данных тикета.

### Где код

- `homeworks/src/day_33_support_assistant/app/main.py` - запуск и вызов LLM
- `homeworks/src/day_33_support_assistant/app/rag.py` - простой retriever по FAQ
- `homeworks/src/day_33_support_assistant/app/context.py` - провайдер контекста
- `homeworks/src/day_33_support_assistant/app/prompting.py` - сборка support-промпта

### Как запустить демо

1. Убедитесь, что в окружении есть ключ провайдера:
   - `LLM_API_KEY`, или
   - `OPENROUTER_API_KEY`, или
   - `GROQ_API_KEY`
2. Запустите:

```bash
python3 -m homeworks.src.day_33_support_assistant.app.main
```

### Пример демо-запроса

- Вопрос: `Почему не работает авторизация?`
- Пользователь: `u_001`
- Тикет: `t_1001` (`last_error = 401 invalid session`)

### Пример демо-ответа

`Ошибка 401 invalid session означает, что сессия недействительна. Это может произойти после смены пароля или если токен сессии истек. Попробуйте войти в систему повторно.`

### Почему это соответствует ДЗ

- Есть ответы о продукте.
- Есть RAG по FAQ/документации.
- Есть учет контекста пользователя и тикета.
- Источник контекста подключен через JSON (допустимый вариант в формулировке задания).
